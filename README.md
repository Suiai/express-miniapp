# 美味点餐小程序

一个基于微信小程序 + 云开发的点餐应用。支持上传菜品照片、名称、描述，确认点餐后通过订阅消息发送微信通知。

## 功能

- 菜品列表浏览（照片、名称、描述、价格，云端共享）
- 添加新菜品（拍照/相册上传照片到云存储）
- 菜品详情查看
- 确认点餐 → 微信订阅消息通知（回执给点餐用户）
- 订单自动记录到云数据库 `orders` 集合（开发者可实时查看）
- 数据存储于云数据库（多用户共享菜单）

## 云开发部署步骤

> 本项目已全面接入微信云开发：云数据库（foods 集合）、云存储（菜品图片）、云函数（通知/初始化）。以下步骤一次性配置后即可长期使用。

### 第 1 步：确认云开发已开通

1. 用微信开发者工具打开 `D:\WorkBuddy\express-miniapp`
2. 点击工具栏「云开发」按钮，确认已开通并有一个可用环境
3. 如提示未开通，按引导开通即可（免费额度足够个人使用）

### 第 2 步：创建云数据库集合

1. 在云开发控制台 →「数据库」→「+」新建集合，命名为 **foods**
2. 点击集合 →「权限设置」→ 选择 **「所有用户可读，仅创建者可读写」**
   （这样所有用户都能看到菜单，只有添加者能修改自己的菜品）

### 第 3 步：部署云函数

分别右键以下两个云函数目录，选择「上传并部署：云端安装依赖」：

1. `cloudfunctions/initFoods` — 初始化示例数据
2. `cloudfunctions/sendOrderNotify` — 发送点餐通知

部署完成后，在云开发控制台「云函数」中找到 `initFoods`，点击「测试」运行一次，将 5 道示例菜品写入数据库。

### 第 4 步：创建订阅消息模板

1. 登录 [微信公众平台](https://mp.weixin.qq.com)
2. 进入「功能」→「订阅消息」→「公共模板库」
3. 搜索并选用包含「名称」「描述」「时间」字段的模板（如点餐类模板）
4. 记下模板 ID

### 第 5 步：配置模板 ID（两处）

1. 打开 `app.js`，将 `subscribeTemplateId` 替换为你的模板 ID
2. 打开 `cloudfunctions/sendOrderNotify/index.js`，将顶部 `TEMPLATE_ID` 替换为同一模板 ID
3. 根据你选用的模板实际字段名，修改云函数中 `data` 的 key（`thing1`/`thing2`/`time3` 需与你模板的关键词顺序一致）

### 第 6 步：验证

1. 首页应显示云端示例菜品（如未显示，点击编译/刷新）
2. 点击「+」添加一道带照片的菜品，保存后返回列表可见
3. 进入任意菜品详情 →「确认点餐」→ 允许订阅授权 → 微信「服务通知」中收到点餐消息

### 第 7 步：查看订单（开发者）

点餐时云函数会把订单自动写入云数据库 **`orders`** 集合（无需手动创建）：

1. 云开发控制台 →「数据库」→ 找到 **orders** 集合
2. 每条记录包含：菜品名称、描述、价格、下单时间、点餐用户 openid、订单状态（pending）
3. 下拉刷新即可看到最新订单

> 注意：通知（订阅消息）只能发给**点餐并授权的用户本人**，这是微信平台规则，无法把顾客的授权转给开发者。开发者查收订单请以 `orders` 集合为准。

## 常见问题

### Q: 首页提示「加载失败」？
A: 检查云开发是否开通、`foods` 集合是否创建、云环境是否已初始化。

### Q: 添加菜品失败？
A: 确认 `foods` 集合已创建，且当前微信账号有写入权限（权限设置为"所有用户可读，仅创建者可读写"）。

### Q: 点餐后收不到微信通知？
A: 按顺序排查：
1. 模板 ID 是否已填入 app.js 和云函数（两处需一致）
2. `sendOrderNotify` 云函数是否已部署
3. 云函数中 `data` 字段 key 是否与模板关键词匹配
4. 是否在真机上测试（模拟器不支持订阅消息弹窗）

### Q: 订阅消息有次数限制吗？
A: 有。用户每次点击授权只允许发送 1 条订阅消息，这是微信平台规则，属正常现象。
